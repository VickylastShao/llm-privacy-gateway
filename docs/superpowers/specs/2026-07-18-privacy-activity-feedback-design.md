# Privacy Activity Feedback Design

**Date:** 2026-07-18

**Status:** Approved for implementation

**Scope:** Windows-first local desktop gateway, OpenAI-compatible and Anthropic Messages routes

## Objective

Give users visible, near-real-time evidence that the local gateway detected and handled sensitive information. Keep the feedback inside the existing single-page workflow and do not create a new store of sensitive request content.

## Product decisions

- Add one `Privacy activity` section below `Model connections`; do not add navigation.
- Persist activity metadata for 168 hours (7 days).
- Keep masked previews only for the lifetime of the desktop process.
- Never persist request bodies, response bodies, original matches, reversible mapping values, or surrounding prompt context.
- Record only requests with at least one privacy detection.
- Show blocked requests as well as pseudonymized, masked, and monitored requests.
- Poll for activity once per second while protection is running and perform a final refresh when protection stops.
- Show 10 activities initially and allow the user to expand the list up to 100.

## Rejected alternatives

### Tauri events only

Events provide lower display latency, but the UI can miss them while hidden, reloading, or not yet mounted. Persistent metadata would still require a query path, producing two synchronization mechanisms.

### SQLite-only activity storage

SQLite-only storage is simpler, but it would require persisting masked previews or omitting them entirely. Persisting previews conflicts with the selected retention policy.

### Original-value activity history

An original-value history would make the privacy tool a concentrated disclosure source. The product will not provide a reveal-original action or store complete matches in activity records.

## Architecture

```text
Protocol request adapter
        |
        v
PrivacyEngine inspection and transformation
        |
        v
RequestPrivacyReport
        |
        v
Gateway final outcome (blocked or forwarded)
        |
        v
ActivitySink
   |                 |
   v                 v
session memory   persistence queue
(with previews)      |
                     v
              SQLite metadata
        |
        v
Tauri query_activity command
        |
        v
React PrivacyActivity section
```

The gateway crate owns only the activity event contract and an `ActivitySink` abstraction. It must not depend on Tauri or `activity-store`. `ActivitySink::publish` accepts an owned safe event and returns whether it was accepted; it never accepts request bytes or original matches. A no-op sink remains available for CLI, tests, and other embedders.

The desktop application supplies an activity service. The service immediately adds a safe event to bounded session memory and enqueues metadata for background SQLite persistence. SQLite work must not execute on an Axum request task.

## Detection reporting

The current protocol adapters call `PrivacyEngine::transform` for individual approved text fields. The implementation adds `transform_reported`, which receives a mutable request report. It appends safe decision metadata immediately after inspection and before enforcing a blocking decision. The existing `transform` method remains a compatibility wrapper that discards the report. Protocol adapters receive one report for the whole request and pass it through every approved field transformation.

Because the caller owns the mutable report, it remains available when `transform_reported` returns `PrivacyError::Blocked`. Protocol-level errors therefore do not discard completed inspection results.

The request report contains:

- normalized entity kind;
- policy action;
- count;
- session-only masked display value, when allowed;
- no original value and no surrounding text.

Protocol adapters aggregate repeated decisions across all inspected request fields. They must continue to mutate only the existing field allowlists. Anthropic signed thinking blocks, identifiers, encrypted fields, unknown fields, and unknown streaming events remain byte-preserved under their existing contracts.

## Activity data contract

Persistent metadata:

```text
id                  UUID generated by the gateway
occurred_at_ms      UTC Unix timestamp in milliseconds
profile_id          authenticated local profile
endpoint            normalized local API route
model               model string, or empty when absent
status              final local/upstream HTTP status
latency_ms          time until a final local result or upstream response headers
category_counts     entity kind to occurrence count
actions             distinct policy actions
request_id          propagated request identifier
```

Session-only additions:

```text
previews             entity kind plus masked display value
preview_available    whether this process still owns the preview
```

Actions use stable machine values: `block`, `pseudonymize`, `mask`, and `monitor`. Entity kinds also use stable machine values such as `api_key`, `china_resident_id`, and `ipv4`. Localization occurs only in the React UI.

## Preview rules

Preview generation occurs while the original field is already in memory. The previewer returns only a new display string and the original match is immediately discarded from the activity path.

- Password, private key, connection string, JWT, and internal hostname: category label only, no character preview.
- API key: provider-style prefix when recognized plus masked body and at most the final three characters.
- China resident ID and unified social credit code: first two and final two characters with the middle masked.
- Bank card: final four digits only.
- IPv4: retain the first and final octet and mask the middle octets.
- IPv6 and MAC address: retain at most the first and final component.
- Coordinate: rounded coarse region is not emitted; show category only.
- Custom terms: category only.

Duplicate masked previews within one activity are deduplicated. The UI displays at most three preview examples per entity kind.

## Persistence and retention

`activity-store` receives a schema version 2 migration that adds `occurred_at_ms` and an index for newest-first queries and retention deletion. Existing version 1 activity rows have no reliable timestamp and are removed during migration; the current released gateway does not populate them.

Repository operations added by the feature:

- insert activity metadata;
- list newest activity metadata with a caller-supplied limit capped at 100;
- delete rows older than 168 hours;
- retain at most 10,000 newest metadata rows as a secondary size bound.

Retention cleanup runs when the desktop state opens and before an activity query. It does not require a permanent timer.

The persistence queue is bounded at 1,024 events. If it is full or persistence fails, gateway request behavior remains unchanged. The activity service increments a dropped-persistence counter, which the UI displays explicitly. Session activity remains visible even when its metadata could not be persisted.

Session memory retains at most 10,000 activity events. When that bound is exceeded, the oldest session preview is removed; its persisted metadata remains available without a preview.

## Desktop API

`query_activity(limit)` returns newest-first activity views, aggregate counts, and service health:

```text
activities
total_activity_count
session_preview_count
persist_dropped_count
retention_hours = 168
```

Each activity view includes persistent metadata, an optional session preview list, and `preview_available`. The Tauri command merges current-process session events with persisted history by activity ID. It never decrypts pseudonym mappings and never returns raw prompt content.

## Single-page interface

The activity section appears below the connection section whenever at least one profile exists. It contains:

- title and concise explanation;
- past-seven-days activity count;
- current-process preview count;
- dropped-persistence warning when nonzero;
- newest-first activity list;
- empty state: `No sensitive information detected yet`;
- `Show more` control that increases the query limit from 10 to 100.

Each collapsed row shows:

- local time;
- connection name and model when available;
- primary action badge;
- entity categories and counts.

Expanding a row shows endpoint, request ID, status, latency, all actions, and masked previews. Historical rows without a current-process preview say that the preview was destroyed with the previous session.

The panel does not expose a raw-value reveal button, manual retention settings, export, filters, or a separate clear-history action in this iteration. Automatic retention keeps the first version self-maintaining.

All new strings are added to both typed English and Simplified Chinese catalogs. Activity rows use semantic buttons, expandable regions, visible focus states, and screen-reader labels. Polling updates must not steal focus or collapse an open row.

## Error handling

- Detection or transformation errors continue to follow the existing fail-closed behavior.
- Activity enqueue, persistence, pruning, or query errors never change proxy response status.
- A query error appears inside the activity section and does not replace the global gateway controls.
- A dropped-persistence count is explicit; the UI must not claim that persisted history is complete when events were lost.
- Poisoned locks and closed worker channels are converted to safe activity-service errors without including request content.

## Testing

### Privacy core

- reports entity kind, action, and safe preview for transformed input;
- preserves the report for blocked input;
- never places original high-risk credential values in report serialization;
- applies every type-specific masking rule.

### Protocol adapters

- aggregates multiple approved fields into one request report;
- reports OpenAI Chat Completions and Responses detections;
- reports Anthropic Messages and count-token detections;
- preserves signed thinking and unknown fields under existing byte-equivalence tests.

### Gateway

- sends one event for a blocked request;
- sends one event for a successfully transformed or monitored request;
- sends no event for a clean request;
- reports endpoint, model, status, latency, profile, and request ID;
- never leaks canary values into the event sink;
- remains functional when the sink rejects an event.

### Activity store and desktop service

- migrates a version 1 database safely;
- writes and lists metadata without sensitive values;
- deletes records older than 168 hours;
- enforces the 10,000-row limit;
- merges session previews with persisted metadata;
- loses previews but retains metadata when the service is recreated;
- reports persistence queue loss.

### React UI

- renders bilingual empty and populated states;
- polls while protection is running and refreshes after stopping;
- renders categories, counts, actions, details, and preview-expired state;
- expands from 10 to at most 100 activities;
- preserves expanded state and focus during refresh;
- displays persistence-loss and query-error messages.

### Regression verification

- frontend tests, TypeScript lint, and production build;
- Rust formatting, Clippy, workspace tests, and dependency audit;
- Node SDK compatibility tests;
- existing canary leak and performance-budget tests;
- Windows-native Tauri release and NSIS packaging.

## Out of scope

- viewing or persisting complete sensitive matches;
- prompt and response history;
- activity export;
- user-configurable retention;
- team administration or remote telemetry;
- browser notifications;
- adding new detector categories such as people or organizations;
- changing the selected privacy policy behavior.
